## Результат `npm run build`

Компиляция 6.8s, TypeScript 9.7s, 44 страницы сгенерированы за 831ms. Ошибок нет.

**Статических маршрутов: 2 из 34.**

```
○ (Static)   /robots.txt, /sitemap.xml
ƒ (Dynamic)  всё остальное — 32 маршрута
```

Причина: `await headers()` в `src/app/layout.tsx` и `src/components/Header.tsx`
(чтение `x-pathname`, который проставляет `middleware.ts`). Пока он там —
ни одна страница не может быть отдана статикой с CDN, каждый запрос идёт
в серверную функцию.

Это целевая метрика шага «route groups»: число `○` должно вырасти с 2 до
большинства публичных страниц.

## Найдено и починено на шаге 2

### `.btn` и `.card` жили в постраничном CSS

`home.css` определял `.btn` и `.card` — с комментарием «generic cards and
buttons used by home sections». Но `.btn` используется на `/about`,
`/articles`, `/client`, `/client/demo-project`, `/commercials`,
`/music-videos` и в `StudioMasthead`, а `home.css` импортируется только
на `/` и `/en`.

Следствие: при холодной загрузке `/client` кнопка была голым текстом.
При переходе на ту же `/client` с главной — оформленной. Замер аудита:

```
.btn borderTopWidth:  холодная=0px    переход=1px
.btn paddingLeft:     холодная=24px   переход=18px
.btn backgroundImage: холодная=none   переход=linear-gradient(...)
```

Одна и та же страница выглядела по-разному в зависимости от маршрута
попадания — то есть баг не воспроизводился по прямой ссылке.

Починено переносом в `shared.css`. Против рецидива — проверка
`SHARED_PRIMITIVES` (голый примитив при холодной загрузке) и
`checkColdVersusClientNav` (сверка отпечатка вёрстки).

### Светлая тема ломает текст поверх тёмных областей — НЕ починено

Три маршрута (`/`, `/en`, `/about`) в светлой теме имеют нечитаемый текст:
контраст 1.06–1.22:1. Корень один — глобальные правила
`html[data-theme="light"] .text-white\/NN { ... !important }` в
`theme.css:442-476` красят текст в тёмные чернила независимо от фона.
Над видео-hero и над тёмными панелями фон остаётся чёрным.

Точечно не чиню: любая заплатка — это ещё одно `!important` в ту же кучу.
Лечится заменой конструкции на семантические токены на шаге «типографика
и токены». До тех пор баги перечислены в `KNOWN_LIGHT_THEME_ISSUES` в
`scripts/frontend-guardrails.mjs`: аудит их показывает как `KNOWN`, но не
валит прогон. Список обязан схлопнуться до нуля и не имеет права расти.
Если известный баг перестал воспроизводиться, аудит потребует убрать его
из списка — чтобы список не протух.

**Починено на шаге 3, см. ниже. `KNOWN_LIGHT_THEME_ISSUES` пуст.**

## Шаг 3: типографика, слои, светлая тема

### Веб-шрифты

Раньше сайт целиком жил на системных стеках, а `--font-display` начинался
с `Iowan Old Style` — шрифта, который есть только на macOS. На Windows
подставлялся Palatino Linotype, на Android — дефолтный serif. Типографика
буквально отличалась у каждого второго посетителя.

Подключены через `next/font/google`, self-хостятся (CSP менять не пришлось):

| | |
|---|---|
| Заголовки | Cormorant Garamond, вариативный |
| Текст и UI | Manrope, вариативный |
| Вес шрифтов | 197 KB на все субсеты |

Оба вариативные, поэтому веса не перечисляются — при перечислении было бы
326 KB. Italic не подключён: в проекте не используется.

### Каскадные слои вместо 138 `!important`

Порядок каскада между глобальным и постраничным CSS не был определён —
побеждал тот чанк, который подгрузился раньше. Это и лечили `!important`:
49 в `theme.css`, 89 в `mobile.css`.

Порядок теперь задан один раз в `globals.css`:

```
hf-base → hf-components → hf-page → hf-mobile → hf-theme
```

`theme.css` последним намеренно: его светлые переопределения обязаны
перебивать постраничный CSS. Токены от позиции не зависят.

Все 138 `!important` удалены. Оставшиеся 28 — законные: 24 внутри
`prefers-reduced-motion`, где `!important` обязателен, один в
`.visually-hidden`, три сбрасывают унаследованную поверхность.

### `.on-dark` — одна строка вместо 35 исключений

Блок из 35 правил светлой темы считает цвет как
`rgb(var(--light-ink) / X)`. Значит переопределение самой переменной
разворачивает весь блок:

```css
.on-dark { --light-ink: 243 243 242; }
```

Вешается на контейнер, фон которого **не** зависит от темы. Помечены:
hero на главной, карточки и таймлайн на `/about`.

У `/about` и `/en/about` помечен весь корень — при проверке выяснилось,
что страница дарк-онли по конструкции: в ней нет ни одной темозависимой
поверхности (`.section-card`, `.section-panel`, `.surface-*`), все фоны
зашиты тёмными градиентами. Светлая тема меняла там только цвет текста,
поэтому текст и пропадал.

### Осталось на будущее

367 вхождений `text-white/NN` в JSX остались как есть. Правильная цель —
семантические классы (`text-ink`, `text-ink-muted`), но это 367 правок в
25 файлах, и делать их осмысленно вместе с введением типографической
шкалы, а не отдельным механическим проходом.
